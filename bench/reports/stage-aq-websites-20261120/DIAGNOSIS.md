## Harness failure

The old experiments already constructed `httpx.AsyncClient(transport=safe_transport(32), trust_env=False)`. No missing production transport factory or proxy configuration explains their uniform ConnectError pattern. Repeating that same factory in the restricted execution context on five previously verified URLs fails at the nested `PermissionError: [WinError 5] Access is denied` (`errno=13`), wrapped as ConnectError / website_connect_error. The same five URLs all return HTTP 200 when that process is authorized for network access: vokser.no, www.aasbetong.no, maaemo.no, skoglundmaskin.no, www.mulligangolf.no. [Successful transport preflight](preflight-authorized.json); [fail-fast restricted preflight](preflight-restricted.json).

This demonstrates an execution-environment denial, not 444/446 independent website failures. The historical requests did not retain full exception chains, so attribution of every old failure individually is not possible. The new harness records cause chains and stops on permission-denied preflight instead of counting an invalid bulk experiment as website rejection evidence. No proxy env, TLS verification or DNS/SSRF rule is changed. Run the harness only in a network-authorized process.

The old harness also created synthetic `{}` registry evidence and measured mutable before/after references. The replacement uses the saved real registry blobs, snapshots baseline counts before mutations, retains saved request usage against caps and applies shared/social/entity guards to the entire cohort. New site counts come from published claims after final vetoes. These are measurement corrections, not new ownership rules.
